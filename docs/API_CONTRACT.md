# PulseStream — API Contract Specification

This document provides the formal contract specification for the PulseStream Event Ingestion API (Milestone 2).

---

## Base Configuration

- **Base URL:** `http://localhost:8080`
- **API Prefix:** `/api/v1`
- **OpenAPI Specification:** `http://localhost:8080/v3/api-docs`
- **Interactive Swagger UI:** `http://localhost:8080/swagger-ui.html`

---

## 1. Event Ingestion Endpoint

### `POST /api/v1/events`

Ingests a user activity event, assigns an event ID (if absent), validates all constraints, and publishes the domain event to Apache Kafka (`user.activity.events`) partitioned by `userId`.

The endpoint returns `202 Accepted` **only after** the Kafka broker acknowledges successful disk persistence across all in-sync replicas (`acks=all`).

---

### Request Headers

| Header | Required | Type | Description |
|---|---|---|---|
| `Content-Type` | **Yes** | String | Must be `application.json` |
| `X-Request-Id` | No | String (UUID) | Client correlation ID. If omitted, the server generates a UUID and returns it in the response header. |

---

### Request Body Schema

```json
{
  "eventId": "4f8a3d5e-2b1c-4e8f-9a3d-5e2b1c4e8f9a",
  "userId": "usr_998877",
  "sessionId": "sess_aabbcc1122",
  "eventType": "PAGE_VIEW",
  "timestamp": "2026-10-09T10:15:30Z",
  "source": "WEB",
  "metadata": {
    "pageUrl": "/products/laptop-pro",
    "referrer": "https://google.com"
  }
}
```

#### Field Specifications

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `eventId` | String | No | Valid UUID (36 chars) or omitted/null | Client-provided idempotency key. Generated by server if omitted. |
| `userId` | String | **Yes** | Non-blank, max 255 chars | Unique identifier for the user. Used as Kafka partition key. |
| `sessionId` | String | **Yes** | Non-blank, max 255 chars | Active session identifier grouping events. |
| `eventType` | String (Enum) | **Yes** | One of: `LOGIN`, `LOGOUT`, `PAGE_VIEW`, `PRODUCT_VIEW`, `SEARCH`, `ADD_TO_CART`, `REMOVE_FROM_CART`, `PURCHASE`, `PROFILE_UPDATE` | Activity type classification. |
| `timestamp` | String (ISO-8601) | **Yes** | Valid ISO-8601 UTC instant (e.g. `2026-10-09T10:15:30Z`) | Client-recorded event occurrence time. |
| `source` | String (Enum) | **Yes** | One of: `WEB`, `MOBILE`, `API` | Originating client platform. |
| `metadata` | Object | No | Arbitrary JSON key-value map | Event-specific contextual metadata. |

---

### Responses

#### `202 Accepted`

Returned when the event is validated and successfully acknowledged by Apache Kafka brokers.

**Response Headers:**
- `Content-Type: application/json`
- `X-Request-Id: <correlation-uuid>`

**Response Body:**
```json
{
  "eventId": "4f8a3d5e-2b1c-4e8f-9a3d-5e2b1c4e8f9a",
  "status": "ACCEPTED",
  "message": "Event accepted and published to stream",
  "timestamp": "2026-10-09T10:15:30.123Z"
}
```

---

#### `400 Bad Request`

Returned when the request violates validation constraints, contains malformed JSON syntax, or supplies invalid enum values.

**Response Body (Validation Failure):**
```json
{
  "timestamp": "2026-10-09T10:15:30.123Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed for request payload",
  "path": "/api/v1/events",
  "requestId": "8f3b2a1c-99d8-472e-83bf-7c8a6b5e4d3c",
  "details": [
    "userId: userId is required and cannot be blank",
    "timestamp: timestamp is required"
  ]
}
```

**Response Body (Invalid Enum Value):**
```json
{
  "timestamp": "2026-10-09T10:15:30.123Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Invalid eventType: 'INVALID_TYPE'. Allowed values: [LOGIN, LOGOUT, PAGE_VIEW, PRODUCT_VIEW, SEARCH, ADD_TO_CART, REMOVE_FROM_CART, PURCHASE, PROFILE_UPDATE]",
  "path": "/api/v1/events",
  "requestId": "8f3b2a1c-99d8-472e-83bf-7c8a6b5e4d3c"
}
```

---

#### `503 Service Unavailable`

Returned when the Apache Kafka broker is unreachable, ISR is down, or broker acknowledgment exceeds the configured timeout (`pulsestream.kafka.publish-timeout-ms=5000`).

**Response Body:**
```json
{
  "timestamp": "2026-10-09T10:15:35.123Z",
  "status": 503,
  "error": "Service Unavailable",
  "message": "Event streaming service temporarily unavailable: Timed out waiting for Kafka broker acknowledgment after 5000ms",
  "path": "/api/v1/events",
  "requestId": "8f3b2a1c-99d8-472e-83bf-7c8a6b5e4d3c"
}
```

## 2. Example `curl` Commands

### Successful Ingestion with Server-Generated Event ID:

```bash
curl -i -X POST http://localhost:8080/api/v1/events \
  -H "Content-Type: application/json" \
  -H "X-Request-Id: a1b2c3d4-e5f6-7890-abcd-ef1234567890" \
  -d '{
    "userId": "usr_1002",
    "sessionId": "sess_8831",
    "eventType": "LOGIN",
    "timestamp": "2026-10-09T10:30:00Z",
    "source": "WEB",
    "metadata": {
      "ip": "203.0.113.195",
      "userAgent": "Mozilla/5.0 Chrome/120.0"
    }
  }'
```

### Successful Ingestion with Client-Provided Event ID:

```bash
curl -i -X POST http://localhost:8080/api/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "eventId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "userId": "usr_1002",
    "sessionId": "sess_8831",
    "eventType": "PURCHASE",
    "timestamp": "2026-10-09T10:35:00Z",
    "source": "MOBILE",
    "metadata": {
      "orderId": "ord_9901",
      "totalAmount": 129.99,
      "currency": "USD"
    }
  }'
```

### Request with Missing Fields (Triggers 400 Bad Request):

```bash
curl -i -X POST http://localhost:8080/api/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "metadata": {}
  }'
```

## 3. Delivery Guarantees & Kafka Architecture

1. **Topic:** `user.activity.events` (configurable via `KAFKA_TOPIC_ACTIVITY_EVENTS`).
2. **Partitioning Key:** `userId`. All events for a specific user land in the same Kafka partition, guaranteeing strict chronological ordering per user.
3. **Producer Acknowledgment:** `acks=all`. The leader and all in-sync replicas must commit the record before acknowledging.
4. **Idempotence:** `enable.idempotence=true` with `max.in.flight.requests.per.connection=1` prevents duplicate records caused by producer network retries while preserving ordering.
5. **Bounded Wait:** The API synchronously awaits broker acknowledgment up to `pulsestream.kafka.publish-timeout-ms` (default 5000ms), ensuring no indefinite thread blocking.
